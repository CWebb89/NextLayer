# Audit, 2026-11-10

A pass over the surfaces of the app, driven with real pointer and keyboard input through
`tools/cockpit`, checking not only that a control draws but that the feature behind it
does what OrcaSlicer or PrusaSlicer does. `tools/check` already proves the engine and the
data paths (12/12 oracle, 44/44 gates); this pass is about the interface and the
workflows on top of them.

Read alongside `docs/features.md` (the inventory) and `docs/known-issues.md` (what is
already known to be wrong). Severities: **blocker** (a workflow cannot be completed, or
data is lost), **major** (works, but differs from the reference in a way a user notices),
**minor** (cosmetic or a rough edge), **unverified** (cannot be exercised here).

## Findings

### 1. Undo after deleting the last object zoomed the camera into the part — FIXED

Open `cube_20.stl`, click it, `Delete`, `Ctrl+Z`. The part comes back and the camera is at
its closest zoom with the bed entirely out of frame; `F` restores the bed fit.

Cause, in `main.qml`: the model-changed handler frames the camera when
`session.path !== root.lastModelPath`, but `lastModelPath` started empty while the model
from the command line is loaded before the QML connects — so the first change to the
document always looked like a new model. `Session::path()` returns `""` for an empty
document too, so delete-then-undo compared twice against an empty baseline. Measured:
`frameContent()` sets `zoom = Host.modelRadius / boundingRadius`, which for a 20 mm cube
is about 0.07, the closest zoom this viewport has.

Fixed by seeding `lastModelPath` from the session in `Component.onCompleted` and ignoring
an empty path. Verified: delete then undo leaves the bed exactly where it was.

### 2. The transform panel reported numbers that belonged to no object — FIXED

Arming Move on a 20 mm cube on a 350 mm bed showed "Centre on X / Y: 125.00 / 110.00" —
the centre of a 250 x 220 bed, hardcoded as property defaults in `TransformPanel.qml`.
Rotate started at `0 / 0 / 45`, Scale at `1.5`, Cut plane Z at `10`, all defaults. The
object list, on the same selection, correctly reported `at 175.0, 175.0`.

Fixed by seeding the panel from `plateDocument.objectInfo()` each time a transform tool is
armed, with `objectInfo` extended to expose all three rotation and scale components.
Verified: the Move panel now reads `175.00 / 175.00` on the 350 mm Voron bed.

### 3. Nothing in the interface undid or redid — FIXED

Undo and redo existed only as `Ctrl+Z` / `Ctrl+Shift+Z`. The plate bar carried open,
object list, delete, duplicate, centre, drop, arrange, auto-orient — everything except the
one command a user reaches for after a mistake. Added undo and redo buttons to that bar,
enabled from `plateDocument.canUndo` / `canRedo`, and routed `Ctrl+Z`/`Ctrl+Shift+Z`
through the same handler so the two cannot drift apart. Verified in a window: both
buttons appear in the toolbar.

### 4. The object context menu truncated its own labels — FIXED

Right-click an object: "Per-object set…", "Lay on face" with a hint cut to "then click a
f…", "Statistics…" with "volume, area, …". The menu was 300 px wide and its hint column
takes up to 46% of that. Widened to 400 px, with the edge clamp derived from the same
number instead of a second hardcoded 320. Verified: "Per-object settings…" and "Statistics
…" now fit whole, and only the hint column elides.

### 5. Two signals nothing emitted — FIXED, and one was load-bearing

`ViewportToolbar.sliceAllRequested` and `Header.sideToggleRequested` were declared and
never emitted or never connected. Removing them exposed a dead `onSliceAllRequested`
handler in `main.qml`, which made QML fail to load ("Cannot assign to non-existent property
onSliceAllRequested") and the app refuse to appear — caught within a minute because the
cockpit reported no window. Slice-all is reachable through the slice button's own menu,
which calls `footer.startSliceAll()` directly, so nothing was lost.

### 6. QML `console.log`, `console.warn` and `print` produce no output at all — OPEN, minor, costs whole sessions

A `console.log` in `Component.onCompleted` printed nothing, and so did `console.error`,
`console.warn` and the QML global `print()`, with `QT_FORCE_STDERR_LOGGING=1` and
`QT_LOGGING_RULES='*.debug=true'` set. QML *engine* diagnostics do get out, because
`main.cpp` hooks `QQmlApplicationEngine::warnings` and prints them to stdout with a `qml:`
prefix — a deliberate syntax error proved that (`QML failed to load ... main.qml:2469:1:
Syntax error`). Only an application's own log lines vanish.

This is exactly why the previous session recorded its paint probe as "inconclusive": the
probe ran and printed nothing. Until the cause is found, debug QML through
`root.setStatus()` (visible in the footer) or a `std::fprintf` on the C++ side.

### 7. Measure cannot place a point anywhere but on a model — OPEN, major

Arm Measure and click twice on the bed: nothing happens, and the status stays "measure:
click two points". `Viewport.addMeasurePoint()` returns early unless `hitAt()` hits a
mesh, so two points on the plate produce no line and no readout. OrcaSlicer measures
between points on the bed as well as on the model, which is what a user does when checking
whether a part fits. Severity is major because the tool looks armed and silently ignores
the click.

### 8. View keys 1–7 die once anything else has focus — OPEN, minor

`1`–`7` (iso, top, bottom, front, rear, left, right) are handled by the viewport item's own
`Keys.onPressed`, so they only work while the viewport holds keyboard focus. After
clicking any toolbar button, dialog or the settings panel they do nothing, with no
indication why. `F`, `R` and `O` are handled at window level and keep working. Either bind
the digits at window level too, or put the view buttons somewhere always reachable.

### 9. Dialogs stay open over the preview — OPEN, minor

Slicing switches to the toolpath view, but the object list and the per-object settings
dialog stay open on top of it, covering the plate and the toolpath. Orca closes the
object manipulation panels when you switch to Preview; the toolpath is the thing you went
there to look at.

### 10. The File menu has no recent files — OPEN, minor

New plate, open, save, save for another slicer, export, send, calibrate, setup,
preferences, shortcuts, about, quit. Both reference slicers carry a recent-files list,
which is how a user reopens the thing they were working on.

### 11. No on-screen object information card — OPEN, minor

Orca shows a card in the viewport's bottom-right with the selected object's name, size,
volume and triangle count. We have the same numbers behind right-click ▸ Statistics…,
so nothing is missing functionally, but the information is one dialog away from the
selection that produced it.

## Reference comparison (OrcaSlicer 2.5-dev, same model, same 350 mm machine)

Both captured on their own workspace with the same 20 mm cube.

- **Prepare layout:** Orca puts the printer/filament/process summary and a Quality /
  Strength / Speed / Support / Multimaterial tab strip down the left, a horizontal tool
  strip across the top of the plate, and a vertical action column on the plate's right
  edge. We use a left settings panel with Process / Filament / Printer tabs and 27
  sub-tabs, a vertical tool rail at the viewport's left, and the same action column on the
  plate. Same family, different axis for the tools.
- **Settings rows:** both show a name, a value, an inline unit switch (`mm` or `%`) and a
  per-setting reset. Ours adds a description tooltip on hover, which Orca also has.
- **Plate chrome:** both draw the plate name at the plate's left edge and the plate number
  at the right; both carry the vendor's bed artwork (the Voron logo).
- **Selection feedback:** Orca tints the object and shows the info card; we tint only.
- **Camera:** Orca frames the object when a model opens; we frame the bed (documented
  open item).
- **Preview:** Orca's legend has a colour-scheme switch (feature / speed / flow / height)
  and per-role visibility checkboxes; ours is a table of role, time, %, usage with the
  palette fixed. Ours answers "how much time and filament is in this feature"; Orca's
  answers "what am I looking at".

## Testing notes (not defects, but they cost time)

- `cockpit drag` needs `--steps 30` or so; with the default the app sees too few motion
  events and the object does not move.
- `cockpit type` drops characters — `type seam` delivered only `s`. Type one character per
  command with a short sleep between them.
- `pkill -f next-layer-qt` matches the shell running the command and kills it (exit 143).
  Use `pkill -x next-layer-qt`.
- A rail click toggles the tool, so a second click on the same icon disarms it; confirm
  with OCR or the status line rather than assuming.
- QML edits need an app restart, and a broken edit leaves the app with no window at all —
  start it under `tools/cockpit/cockpit start` and read the "nothing appeared" message.
